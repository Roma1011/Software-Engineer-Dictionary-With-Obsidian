### Fork

**Fork** ინგლისურად ჩანგალს და გზის გაყოფის ადგილს ნიშნავს, ანუ წერტილს, სადაც ერთი გზა ორად იყოფა. პროგრამირებაში აზრი იგივეა: **არსებულიდან იქმნება დამოუკიდებელი ასლი, რომელიც შემდეგ თავისი გზით ვითარდება**.

```
         ┌──► ასლი (თავისი გზით ვითარდება)
საწყისი ─┤
         └──► ორიგინალი (აგრძელებს თავის გზას)
```

**ახსნა:**
ტერმინი რამდენიმე კონტექსტში გვხვდება: Git/GitHub, ღია კოდის პროექტები, ოპერაციული სისტემის პროცესები და პარალელური გამოთვლები. ყველგან ერთი იდეაა: **ერთიდან ხდება ორი**, და ისინი ერთმანეთისგან დამოუკიდებლად აგრძელებენ.

#### 1. Git და GitHub: რეპოზიტორიის fork

GitHub-ზე (GitLab-ზე, Bitbucket-ზე) fork არის **სხვისი რეპოზიტორიის სრული ასლი თქვენს ანგარიშზე, სერვერზევე**. ორიგინალში ჩაწერის უფლება თქვენ არ გაქვთ, თქვენს fork-ში კი რაც გინდათ, იმას აკეთებთ.

```
upstream:  github.com/dotnet/runtime              ← ორიგინალი (ჩაწერის უფლება არ გაქვთ)
   │
   │  Fork (ღილაკი GitHub-ზე)
   ▼
origin:    github.com/<თქვენი-ანგარიში>/runtime   ← თქვენი ასლი სერვერზე
   │
   │  git clone
   ▼
ლოკალური ასლი თქვენს კომპიუტერზე
```

ტიპური სამუშაო პროცესი ასეთია:

```bash
# 1. GitHub-ზე დააჭირეთ Fork-ს, შემდეგ თქვენი fork ჩამოტვირთეთ
git clone https://github.com/<თქვენი-ანგარიში>/runtime.git
cd runtime

# 2. დაამატეთ ორიგინალი, როგორც "upstream"
git remote add upstream https://github.com/dotnet/runtime.git

# 3. იმუშავეთ ცალკე branch-ზე და ატვირთეთ თქვენს fork-ში
git checkout -b fix-typo
git commit -am "Fix typo in docs"
git push origin fix-typo

# 4. GitHub-ზე გახსენით Pull Request: თქვენი fork → upstream
```

fork-ი ორიგინალის ცვლილებებს **ავტომატურად არ იღებს**. ძველი რომ არ დარჩეს, ორიგინალიდან ცვლილებები თავად უნდა ჩამოიტანოთ:

```bash
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```

> [!TIP] როდის fork და როდის branch
> თუ რეპოზიტორიაში ჩაწერის უფლება **გაქვთ** (თქვენი გუნდის პროექტია), საკმარისია **branch**. fork საჭიროა მაშინ, როცა უფლება **არ გაქვთ**: ღია კოდის პროექტში წვლილის შესატანად, ან სხვისი პროექტის საფუძველზე საკუთარის დასაწყებად.

|ცნება|სად იქმნება|რას ნიშნავს|
|---|---|---|
|**Fork**|სერვერზე (GitHub), თქვენს ანგარიშზე|მთელი რეპოზიტორიის დამოუკიდებელი ასლი|
|**Clone**|თქვენს კომპიუტერზე|რეპოზიტორიის ლოკალური ასლი|
|**Branch**|იმავე რეპოზიტორიის შიგნით|განვითარების ცალკე ხაზი|

#### 2. პროექტის fork (ღია კოდი)

უფრო ფართო მნიშვნელობით fork ნიშნავს, რომ **პროექტი ორად გაიყო**: ნაწილმა დეველოპერებმა კოდის ასლი აიღო და ცალკე, ახალი სახელით განაგრძო. ეს ჩვეულებრივ ხდება ლიცენზიის შეცვლის, მფლობელთან უთანხმოების ან პროექტის მიტოვების გამო.

|ორიგინალი|fork|
|---|---|
|OpenOffice|LibreOffice|
|MySQL|MariaDB|
|Terraform|OpenTofu|
|Redis|Valkey|

ასეთი fork-ის შემდეგ ორი პროექტი ხშირად ერთმანეთს სულ უფრო შორდება და საბოლოოდ სხვადასხვა პროდუქტად იქცევა.

#### 3. პროცესის fork (ოპერაციული სისტემა)

Unix/Linux-ში `fork()` არის სისტემური გამოძახება, რომელიც **მიმდინარე პროცესის ასლს ქმნის**. ახალ პროცესს **შვილი** (child) ჰქვია, ძველს **მშობელი** (parent). `fork()`-ის შემდეგ ორივე ერთსა და იმავე ადგილიდან აგრძელებს შესრულებას, და მათ მხოლოდ დაბრუნებული მნიშვნელობით არჩევთ:

```c
pid_t pid = fork();

if (pid == 0) {
    // შვილი პროცესი: fork()-მა 0 დააბრუნა
    printf("მე შვილი ვარ\n");
}
else if (pid > 0) {
    // მშობელი პროცესი: fork()-მა შვილის PID დააბრუნა
    printf("მე მშობელი ვარ, შვილის PID = %d\n", pid);
}
else {
    // pid < 0: პროცესის შექმნა ვერ მოხერხდა
    perror("fork");
}
```

შვილი პროცესი მშობლის მეხსიერების ასლს იღებს, მაგრამ სისტემა მას მაშინვე არ აკოპირებს. ამ ხერხს **copy-on-write** ჰქვია (იხ. [[Copy-on-Write]]): გვერდები საერთოა, სანამ რომელიმე პროცესი მათში ჩაწერას არ ცდილობს, და მხოლოდ მაშინ კოპირდება.

ხშირად `fork()`-ს მაშინვე `exec()` მოსდევს: შვილი პროცესი თავის კოდს სხვა პროგრამით ცვლის. ასე უშვებს shell-ი ბრძანებებს.

> [!NOTE] .NET-ში
> C#-ში `fork()` პირდაპირ არ გამოიყენება. ახალი პროცესი `Process.Start(...)`-ით იქმნება, Linux-ზე კი .NET შიგნით სწორედ fork და exec მექანიზმს იყენებს.

#### 4. Fork/Join (პარალელური გამოთვლა)

**Fork/Join** არის შაბლონი, სადაც სამუშაო **იყოფა** (fork) რამდენიმე დამოუკიდებელ ნაწილად, ისინი **პარალელურად** სრულდება, შემდეგ კი ყველას **ელოდებით და შედეგებს აერთიანებთ** (join, იხ. [[Join]]).

```
             ┌──► GetUserAsync    ──┐
მოთხოვნა ────┼──► GetOrdersAsync  ──┼──► Join ──► Dashboard
   (fork)    └──► GetBalanceAsync ──┘
```

C#-ში ეს ყველაზე ხშირად `Task.WhenAll`-ით კეთდება:

```csharp
public async Task<Dashboard> LoadDashboardAsync(int userId)
{
    // Fork: სამივე მოთხოვნა ერთდროულად იწყება
    Task<User> userTask = GetUserAsync(userId);
    Task<List<Order>> ordersTask = GetOrdersAsync(userId);
    Task<decimal> balanceTask = GetBalanceAsync(userId);

    // Join: ველოდებით, სანამ ყველა არ დასრულდება
    await Task.WhenAll(userTask, ordersTask, balanceTask);

    return new Dashboard(await userTask, await ordersTask, await balanceTask);
}
```

თუ თითოეულს რიგრიგობით დაელოდებით (`await GetUserAsync(...)`, შემდეგ `await GetOrdersAsync(...)`), მთლიანი დრო **ჯამი** იქნება. Fork/Join-ით კი დრო დაახლოებით **ყველაზე ნელი** ოპერაციის ტოლია.

CPU-ზე დამოკიდებული სამუშაოსთვის იგივე იდეა `Parallel.For`/`Parallel.ForEach`-შია ჩადებული: მონაცემები ნაწილებად იყოფა, ნაწილები სხვადასხვა ნაკადზე მუშავდება, და მეთოდი მხოლოდ მაშინ ბრუნდება, როცა ყველა დასრულდება (იხ. [[CPU-Bound]]).

|**Fork**|„ერთიდან ორი": დამოუკიდებელი ასლი, რომელიც თავისი გზით აგრძელებს|

|**[[Join]]**|პარალელურად გაშვებული ნაწილების დასრულების მოლოდინი და შედეგების გაერთიანება|
