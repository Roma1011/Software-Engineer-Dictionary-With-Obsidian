### Join

**Join** ნიშნავს **რამდენიმე ცალკეული ნაწილის ერთად შეერთებას**. პროგრამირებაში ეს ორ ძირითად აზრს ატარებს:

1. **ნაკადების ან ამოცანების join:** ცალ-ცალკე გაშვებულ სამუშაოებს ელოდებით, სანამ ყველა არ დასრულდება, და მათი შედეგები ერთ წერტილში ერთიანდება. ეს [[Fork]]-ის საპირისპირო ნაბიჯია: fork ყოფს, join აერთებს.
2. **მონაცემების join:** ორი ცხრილის ან კოლექციის ჩანაწერებს ერთმანეთს რაიმე საერთო გასაღებით უწყვილებთ (SQL, LINQ).

```
Fork / Join:                          მონაცემების Join:

        ┌──► A ──┐                    Customers ──┐
საწყისი ┼──► B ──┼──► Join ──► შედეგი              ├── Id = CustomerId ──► წყვილები
        └──► C ──┘                    Orders ─────┘
```

**ახსნა:**
ორივე შემთხვევაში join არის **შეერთების წერტილი**: ერთგან დროში (ველოდებით, სანამ პარალელური ნაწილები დასრულდება), მეორეგან მონაცემებში (ვუწყვილებთ ჩანაწერებს).

#### 1. ნაკადის join: `Thread.Join`

`Thread.Join()` მიმდინარე ნაკადს **ბლოკავს**, სანამ მითითებული ნაკადი არ დასრულდება:

```csharp
var worker = new Thread(() =>
{
    Thread.Sleep(1000);
    Console.WriteLine("სამუშაო დასრულდა");
});

worker.Start();      // Fork: ახალი ნაკადი იწყებს მუშაობას
worker.Join();       // Join: აქ ველოდებით, სანამ worker არ დასრულდება
Console.WriteLine("ახლა შეგვიძლია გავაგრძელოთ");
```

`Join`-ის გარეშე მთავარი ნაკადი მეორე `WriteLine`-ს შეიძლება worker-ის დასრულებამდე შეასრულებდეს.

#### 2. Fork/Join ამოცანებით: `Task.WhenAll`

თანამედროვე C#-ში ნაკადების ხელით შექმნის ნაცვლად ამოცანებს (`Task`) იყენებენ, join-ის როლს კი `Task.WhenAll` ასრულებს. განსხვავება ისაა, რომ `await Task.WhenAll(...)` ნაკადს **არ ბლოკავს**:

```csharp
// Fork: სამივე ჩამოტვირთვა ერთდროულად იწყება
Task<string> a = http.GetStringAsync(urlA);
Task<string> b = http.GetStringAsync(urlB);
Task<string> c = http.GetStringAsync(urlC);

// Join: ველოდებით ყველას, შედეგები ერთ მასივად მოდის
string[] pages = await Task.WhenAll(a, b, c);
```

> [!TIP] Join-ის ვარიანტები
> `Thread.Join()` და `Task.Wait()` ნაკადს ბლოკავს. `await Task.WhenAll(...)` ელოდება ბლოკირების გარეშე. `Task.WhenAny(...)` კი **პირველს** ელოდება, ყველას არა.

#### 3. SQL JOIN

SQL-ში `JOIN` ორი ცხრილის სტრიქონებს **პირობით უწყვილებს**. ავიღოთ ორი ცხრილი:

```
Customers               Orders
Id | Name               Id | CustomerId | Total
---+-------             ---+------------+------
1  | ანა                10 | 1          | 50
2  | გიორგი             11 | 1          | 30
3  | ნინო               12 | 2          | 70
                        13 | 9          | 20    ← ასეთი მომხმარებელი არ არსებობს
```

```sql
SELECT c.Name, o.Total
FROM Customers c
INNER JOIN Orders o ON o.CustomerId = c.Id;
```

სხვადასხვა JOIN სხვადასხვა შედეგს იძლევა:

|JOIN|რას აბრუნებს|ამ მაგალითში|
|---|---|---|
|**INNER JOIN**|მხოლოდ ის წყვილები, რომლებსაც ორივე მხარეს აქვთ დამთხვევა|ანა 50, ანა 30, გიორგი 70|
|**LEFT JOIN**|მარცხენა ცხრილის ყველა სტრიქონი, დამთხვევის არქონისას მარჯვენა მხარე `NULL`|+ ნინო `NULL`|
|**RIGHT JOIN**|მარჯვენა ცხრილის ყველა სტრიქონი, დამთხვევის არქონისას მარცხენა მხარე `NULL`|+ `NULL` 20|
|**FULL OUTER JOIN**|ორივე ცხრილის ყველა სტრიქონი|+ ნინო `NULL`, + `NULL` 20|
|**CROSS JOIN**|ყველა სტრიქონი ყველასთან (პირობის გარეშე)|3 × 4 = 12 წყვილი|

> [!WARNING]
> თუ `ON` პირობა დაგავიწყდათ ან არასწორია, JOIN ბევრად მეტ სტრიქონს დააბრუნებს, ვიდრე ელოდით (CROSS JOIN-ის მსგავსად). მსხვილ ცხრილებზე ეს მოთხოვნას მკვეთრად ანელებს.

#### 4. LINQ: `Join` და `GroupJoin`

LINQ-ში `Join` იგივე INNER JOIN-ია, ოღონდ მეხსიერებაში არსებულ კოლექციებზე:

```csharp
var result = customers.Join(
    orders,
    c => c.Id,               // გასაღები მარცხნივ
    o => o.CustomerId,       // გასაღები მარჯვნივ
    (c, o) => new { c.Name, o.Total });

// ანა 50, ანა 30, გიორგი 70
```

`GroupJoin` თითოეულ მომხმარებელს მის **ყველა** შეკვეთას ერთ ჯგუფად აწვდის, მათ შორის ცარიელ ჯგუფს, თუ შეკვეთა არ აქვს:

```csharp
var perCustomer = customers.GroupJoin(
    orders,
    c => c.Id,
    o => o.CustomerId,
    (c, os) => new { c.Name, Count = os.Count() });

// ანა 2, გიორგი 1, ნინო 0
```

.NET 10-დან LINQ-ს `LeftJoin` და `RightJoin` ოპერატორებიც აქვს. მანამდე LEFT JOIN-ს `GroupJoin` + `SelectMany` + `DefaultIfEmpty()`-ით აკეთებდნენ.

#### 5. სტრიქონების join: `string.Join`

უფრო მარტივი მნიშვნელობით join ნიშნავს **ელემენტების ერთ სტრიქონად შეერთებას** გამყოფით:

```csharp
string[] tags = { "csharp", "dotnet", "linq" };
string line = string.Join(", ", tags);   // "csharp, dotnet, linq"
```

საპირისპირო ოპერაციაა `Split`: `line.Split(", ")` სტრიქონს ისევ მასივად დაშლის.

|კონტექსტი|რას აერთებს|C# / SQL|
|---|---|---|
|**ნაკადი**|ელოდება ნაკადის დასრულებას|`Thread.Join()`|
|**Fork/Join**|პარალელური ამოცანების შედეგებს|`await Task.WhenAll(...)`|
|**SQL**|ორი ცხრილის სტრიქონებს პირობით|`INNER / LEFT / RIGHT / FULL / CROSS JOIN`|
|**LINQ**|ორი კოლექციის ელემენტებს გასაღებით|`Join`, `GroupJoin`, `LeftJoin`|
|**სტრიქონი**|ელემენტებს ერთ სტრიქონად|`string.Join(", ", items)`|

|ტერმინი|აღწერა|
|---|---|
|**Join**|შეერთების წერტილი: დროში (ლოდინი) ან მონაცემებში (დაწყვილება)|
|**[[Fork]]**|საპირისპირო ნაბიჯი: ერთიდან რამდენიმე დამოუკიდებელი ნაწილის შექმნა|
|**Join key**|ველი, რომლითაც ჩანაწერები ერთმანეთს უწყვილდება (მაგალითად, `CustomerId`)|
